     1	# Contributing to Sentinel API
     2	
     3	## Setup
     4	
     5	```bash
     6	git clone https://github.com/PetrefiedThunder/sentinel-api
     7	cd sentinel-api
     8	uv venv && source .venv/bin/activate
     9	uv sync
    10	pre-commit install
    11	```
    12	
    13	You need Postgres ≥ 15 and Redis ≥ 6 running locally:
    14	
    15	```bash
    16	createdb sentinel
    17	export DATABASE_URL="postgresql+asyncpg://localhost/sentinel"
    18	export REDIS_URL="redis://localhost:6379/0"
    19	export JWT_SECRET="$(openssl rand -hex 32)"
    20	
    21	alembic upgrade head
    22	uvicorn app.main:app --reload
    23	```
    24	
    25	## Running tests
    26	
    27	```bash
    28	pytest -q                                  # all tests
    29	pytest tests/test_approvals.py -v          # one file
    30	pytest -k "rejection"                      # by name pattern
    31	```
    32	
    33	## Migrations
    34	
    35	```bash
    36	# create
    37	alembic revision -m "your change"          # edits the file by hand
    38	# apply
    39	alembic upgrade head
    40	# round-trip test before pushing
    41	alembic downgrade -1 && alembic upgrade head
    42	```
    43	
    44	**Migration rules:**
    45	
    46	- Sequential numeric prefix: `007_<short_name>.py`
    47	- `revision = "007"` and `down_revision = "006"` — strings must match exactly
    48	- One logical change per migration
    49	- All migrations must be reversible (`downgrade()` implemented)
    50	- Test round-trip locally before pushing
    51	
    52	## Pull requests
    53	
    54	1. Open an issue first if it's a behavior change
    55	2. Small, focused PRs
    56	3. Add tests
    57	4. `pytest` + `ruff check .` must pass (pre-commit enforces this)
    58	5. Document any new env var in README.md
    59	6. If you add a migration, link to it in the PR description
    60	
    61	## Release process
    62	
    63	The API is continuously deployed from `main`. There is no version tag — every merge to `main` is the new production version. If you need a hotfix, push to `main` and watch Railway auto-deploy.
    64	
    65	## Security
    66	
    67	See [`SECURITY.md`](SECURITY.md). Never file a public issue for a vulnerability.
    68	
    69	## Code style
    70	
    71	- Python 3.11+
    72	- Type hints required on all public APIs (`mypy` in pre-commit)
    73	- `ruff` for lint + format (config in `pyproject.toml`)
    74	- Async-first (`async def` for any DB-touching code)
    75	
    76	## Code of conduct
    77	
    78	Be excellent. Harassment, discrimination, or bigotry → removed from the project.
